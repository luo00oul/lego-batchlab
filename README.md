## 题目说明

给定按固定顺序排列的 `n` 个作业。第 `i` 个作业的执行时间为 `t[i]`，费用系数为 `f[i]`。必须将它们划分成若干**连续批次**，不能交换作业顺序。每批先消耗启动时间 `S`，再消耗批内作业的执行时间；同一批的所有作业在该批结束时一起完成。

若作业 `i` 的完成时刻为 `C[i]`，目标是求最小总费用及对应的一种最优划分：

```text
totalCost = Σ(i=1…n) f[i] × C[i]
```

最优划分可能不唯一；网站和 C++ 程序会按确定的并列处理规则给出其中一种。

### 默认案例：为什么答案是 153？

```text
n = 5，S = 1
t = [1, 3, 4, 2, 1]
f = [3, 2, 3, 3, 4]
一种最优划分：[1,2] | [3] | [4,5]
```

| 批次 | 本批耗时 | 本批结束时刻 | 该批开始时未完成作业的系数和 | 这段时间产生的费用贡献 |
| --- | ---: | ---: | ---: | ---: |
| `[1,2]` | `1+1+3=5` | 5 | `3+2+3+3+4=15` | `5×15=75` |
| `[3]` | `1+4=5` | 10 | `3+3+4=10` | `5×10=50` |
| `[4,5]` | `1+2+1=4` | 14 | `3+4=7` | `4×7=28` |
| **合计** | | | | **153** |

同样可以直接按作业计算：`C=[5,5,10,14,14]`，所以 `3×5+2×5+3×10+3×14+4×14=153`。网页“积木分批”中的“本批费用”按**本批作业的 `f[i]×C[i]`**统计；上表按**每段批次时间对所有尚未完成作业的影响**统计。两种拆法的分组数值不同，总和相同。

## 核心一：朴素动态规划 O(n²)

### 1. 前缀和

定义 `T[0]=F[0]=0`，并令：

```text
T[i] = t[1] + t[2] + … + t[i]   前 i 个作业的累计执行时间
F[i] = f[1] + f[2] + … + f[i]   前 i 个作业的累计费用系数
```

因此，连续区间 `j+1…i` 的执行时间是 `T[i]−T[j]`，而作业 `j+1…n` 的费用系数和是 `F[n]−F[j]`。

### 2. 状态的准确含义

`dp[i]`（有些课件写作 `d[i]`）表示：**处理完前 `i` 个作业时，已经发生的批次时间对全部 `n` 个作业最终费用造成的最小累计贡献**。尚未处理的作业也已经被前面流逝的时间推迟，因此 `dp[i]` 不能简单解释为“前 `i` 个作业自身的最小费用”。初始值 `dp[0]=0`，最终答案是 `dp[n]`。

### 3. 枚举最后一批

假设当前最后一批包含作业 `j+1…i`，其中 `0≤j<i`。这批的耗时为 `S+T[i]−T[j]`。在它开始时，作业 `j+1…n` 都尚未完成，这段时间会同时推迟它们，因此新增费用为：

```text
(S+T[i]−T[j]) × (F[n]−F[j])
```

遍历所有合法 `j` 即得转移：

```text
dp[i] = min_{0≤j<i} { dp[j] + (S+T[i]−T[j]) × (F[n]−F[j]) }
```

每个方案的最后一批一定有某个合法的 `j`；去掉该批后，前面的批次必须按相同目标取得最小贡献，否则可以替换成更优前缀。这说明上述枚举既覆盖所有方案，也满足最优子结构。记录取得最小值的 `prev[i]=j`，从 `i=n` 沿 `prev` 逆推即可恢复批次。

## 核心二：单调凸壳优化 O(n)

将查询时已知的 `i` 放入横坐标 `x=S+T[i]`，把每个历史状态 `j` 写成直线：

```text
y_j(x) = −F[j] × x + dp[j] − T[j] × (F[n]−F[j])
dp[i] = x × F[n] + min_{0≤j<i} y_j(x)
```

这一步只是在重排同一个转移式；每条直线的斜率为 `−F[j]`，截距为 `dp[j]−T[j](F[n]−F[j])`。求 `dp[i]` 时只查询此前已生成的 `j<i`，算出 `dp[i]` 后才将状态 `i` 的新直线加入队列。

当 `t[i]≥0`、`f[i]≥0` 时，查询横坐标 `x` 单调不减，新增直线的斜率单调不增。维护对**后续查询**有效的下凸壳，每条线摊还只需有限次入队、出队操作。实现用整数叉积判断三条线的相对位置，避免浮点交点误差；等斜率时保留更低截距，并对费用并列采用确定的选取规则。某条线从队列移除，只说明它在之后的单调查询中不再需要，并非说它在所有实数横坐标上都不可能最优。

| 方法 | 时间复杂度 | 主要用途 |
| --- | --- | --- |
| 暴力枚举全部分批 | 指数级 | 小规模正确性对照 |
| 朴素动态规划 | `O(n²)` | 展示每个候选 `j` 的真实比较过程 |
| 单调凸壳动态规划 | 摊还 `O(n)` | 快速求解并展示几何优化过程 |

浏览器端使用 `BigInt` 进行费用运算，并校验输入为非负 JavaScript 安全整数，作业数范围为 `1…5000`。C++17 版本用 `__int128` 保存中间量和答案，接受 `0≤S,t[i],f[i]≤10^7`。两端的输入上限不同；课堂默认案例均在范围内。

## 常见问题与易错点

**为什么 `dp[i]` 不是“前 `i` 个作业的最小费用”？** 之前每一批花掉的时间，同样推迟了后续作业。转移按所有当时尚未完成的作业计费，所以 `dp[i]` 包含这些未来作业的等待贡献；只有 `dp[n]` 才是完整方案的总费用。

**为什么网页“本批费用”和转移式中的单批增量不同？** 前者按同批完成的作业计算 `Σ f[i]C[i]`；后者按一段批次时间对所有未完成作业计算。两者是在不同方向上分摊同一总费用。

**为什么凸壳能删除候选？** 因为后续查询的 `x` 不会向左移动；被移除的线对之后的查询已无优势。不能据此断言它在整个实数轴上都无用。

**零值、等斜率和费用相同怎么办？** `t[i]=0` 允许相同查询横坐标，`f[i]=0` 允许相同斜率；代码用精确整数比较处理这些情况，并稳定地选取一种最优划分。

## 本地运行与测试

需要 Node.js **20 或更新版本**。执行跨语言测试还需要支持 C++17 的 `g++`。在项目根目录运行：

```bash
npm ci
npm run dev
```

终端会显示本地访问地址。构建与自动化测试命令为：

```bash
npm run build
npm test
```

`npm test` 覆盖默认案例、单作业、`S=0`、零时间/零系数、相同斜率、并列最优、多组随机小数据的暴力/朴素 DP/凸壳一致性，以及 **80 组** C++ 与 TypeScript 跨语言对照。`npm run build` 包含 TypeScript 类型检查和 Vite 生产构建。

### 独立运行 C++17 程序

程序在**当前工作目录**读取 `input.txt`，把**最小费用一行**写入 `output.txt`；分批方案另写到标准错误输出，不改变 `output.txt` 的题目格式。项目根目录已经提供默认输入。

```bash
g++ -std=c++17 -O2 cpp/batchlab.cpp -o batchlab
./batchlab
cat output.txt
```

在 Windows PowerShell 中，可以编译为 `batchlab.exe`，然后运行 `./batchlab.exe`，用 `Get-Content output.txt` 查看结果。默认案例输出为 `153`。
